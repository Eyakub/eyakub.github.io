git push starts a workflow with on: push. pull_request can start one too.

ubuntu-latest is a fresh virtual machine. Each job gets its own.

actions/checkout downloads the commit. Then install. A cache can skip the download.

A nonzero test exit fails the step. Later steps are skipped.

The job pushes app:3f9c2a1 to ghcr.io. The tag is the commit SHA, never latest.

The deploy job needs the build, then waits on environment: production.

Approve and deploy, or reject and fail the run. Secrets come after the yes.

The released job tells the production server to run app:3f9c2a1.

Then the production server pulls that tag from ghcr.io. The tested bytes are the bytes that run.

The run ends green. Rollback is one deploy of the previous SHA.

Blue-green keeps two production servers. Blue is live. Green is idle.

The new tag lands on the green production server. Blue still serves customers.

A health check hits the green production server directly. Traffic stays on blue.

The router sends production traffic to green. Blue stays up for a switch back.
