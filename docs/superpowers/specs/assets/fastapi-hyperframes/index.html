Off this path: 422 never enters your function. An unhandled exception becomes 500, and CORSMiddleware adds no headers to it. Lifespan runs once in each worker.

Uvicorn parses the HTTP bytes with h11 or httptools, builds an ASGI scope, and calls await app(scope, receive, send). FastAPI never touches the socket.

FastAPI subclasses Starlette. ServerErrorMiddleware is always the outermost layer, so any unhandled exception becomes a 500.

With add_middleware, the last one added is the outermost and runs first on the way in. The request goes top to bottom, and the response goes bottom to top.

ExceptionMiddleware sits innermost, around the router. It turns HTTPException and your registered handlers into responses.

The Router matches path and method and extracts path params like item_id. A missing path is 404, a wrong method is 405, and mounted sub-apps resolve here.

solve_dependencies runs each Depends, sub-dependencies first and cached per request, and the setup half of yield dependencies. Pydantic validates path, query, and body.

A def handler runs in a threadpool, an AnyIO worker thread. An async def handler runs on the event loop, so a blocking call inside it freezes every request.

response_model filters as the value leaves. Pydantic drops extra fields, then it becomes a JSONResponse. ORM objects need from_attributes=True.

The response flows back through the router and ExceptionMiddleware. That layer steps in only if an exception was raised.

The response passes your middleware from bottom to top, then ServerErrorMiddleware. CORS and GZip add headers or compression on this leg.

Uvicorn sends http.response.start and http.response.body. Status, headers, and body go on the wire. The client is done.

BackgroundTasks run after the response is sent, in the same process, with no retries. If the process dies, the task is lost. Yield dependency teardown also runs after, by default.
