t = threading.Thread(target=work)

print(t.ident, t.is_alive()) # None False

t.start() # at most once, then run

threading.stack_size(0) # platform default, min 32 KiB

t.daemon = True # before start, or RuntimeError

t.join(1.0) # returns None; still = t.is_alive()

stop = threading.Event() # stop.wait() until stop.set()

threading.excepthook # ignores SystemExit

Off this path: A daemon thread is stopped abruptly when the process exits, so open files and transactions may not be cleaned up. join before start, or joining the current thread, raises RuntimeError.

The Thread object exists before any kernel thread. ident is None until start, and is_alive is false. daemon must be set before start, or you get RuntimeError. The main thread is not a daemon, so a thread it creates starts non-daemon.

start runs at most once and calls run on the new thread. is_alive is true from just before run until just after it returns. native_id is the kernel id, and it stays unique only until the thread ends.

On a default build, bytecode runs while this thread holds the GIL, so only one thread runs it. stack_size(0) keeps the platform default. The smallest size you may ask for is 32 KiB. The docs never state an 8 MB default.

A real blocking call releases the GIL, and the kernel marks the thread blocked. Another Python thread can run. Threads help waiting. They do not speed up pure-Python number work.

The kernel makes the thread runnable again. The next Python instruction still waits until this thread holds the GIL.

When run returns, is_alive becomes false. An exception there goes to threading.excepthook, which ignores SystemExit. join blocks the caller and returns None. After a timeout, call is_alive.
