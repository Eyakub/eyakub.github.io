Off this path: A killed process leaves the other process running. A hard fault in one thread takes down the whole process. A plain Python exception ends only that thread.

Thread 1 stores into a heap object. Threads in one process share one address space: globals, heap and open files.

Thread 2 reads the same object directly: no copy, no serialization, no IPC. Cheap, but shared mutable state needs synchronization.

Writes are visible to every thread of A at once. That is both the power and the hazard of threads.

Processes have separate address spaces. A multiprocessing Queue or Pipe pickles the object into bytes and sends them over an OS pipe or socket.

The receiving process reads the bytes. Cost grows with object size, and the object must be picklable.

Unpickling builds a new object in B's heap. It is a copy, not the same object. For real sharing, use shared_memory or Value/Array.

B mutates only its private heap. Nothing in process A can see this write.

Isolation is the main benefit of processes: no accidental sharing, no memory data races, and each process has its own GIL.

Results return the same way: pickled, then copied. This IPC cost is why chunking work into larger tasks matters.

Thread 1 unpickles a new object in A's heap. Sharing in Python threads is free; across processes every hand-off is a copy.
