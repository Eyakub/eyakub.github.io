Off this path: time.sleep or requests.get inside async def never yields, so every request waits. to_thread only keeps I/O off the loop; CPU-bound work needs a ProcessPoolExecutor. FastAPI runs def routes in AnyIO's threadpool.

create_task or gather wraps each coroutine in a Task and schedules its first step in the loop's ready queue.

The loop takes one callback from the ready queue and runs it until the coroutine awaits. Nothing else runs meanwhile: scheduling is cooperative.

await on an unfinished future suspends the coroutine and returns control to the loop. The socket is registered with the selector: epoll on Linux, kqueue on macOS and BSD.

This is the whole benefit. While A waits for I/O, B uses the thread, and waiting costs no CPU.

B registers its socket with the selector as well. Both tasks are now pending, and the ready queue is empty.

When idle, the loop blocks in select(timeout), where the timeout is the time to the next timer. The kernel tracks readiness, so many sockets cost little.

The kernel marks A's socket readable, so the blocked select call returns.

The loop learns that A's socket is ready and marks A ready to resume. Nothing has resumed A yet.

The Task continues the coroutine right after its await, with the received bytes as the result. A runs until it finishes or awaits again.

The Task completes and its done-callbacks are scheduled. One thread served both tasks: concurrent, but never parallel.
