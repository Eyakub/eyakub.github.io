Off this path: The formulas ignore split and merge overhead, so two cores can finish later than one. A default build runs Python bytecode on one thread. Processes, a C extension that releases the lock, a free-threaded build, or InterpreterPoolExecutor can use two cores.

Startup, reading the input, and the final merge are serial. Extra cores sit idle while one core does that stretch.

One core takes the setup. The second core stays idle until a piece can run on its own.

Two instruction streams, one instant. That needs more than one core, and a runtime that is allowed to use both.

Wall-clock time is the serial stretches plus the longer parallel part, plus what the split itself cost.

Amdahl fixes the job size. Speedup is 1 / ((1 - p) + p / n), with p the fraction that splits. At p of 0.95 the ceiling is 20 times. At p of 0.5 it is 2 times.

Gustafson-Barsis, 1988, grows the job with the machine. Scaled speedup is about n - s(n - 1), where s is the serial share of the parallel run. Amdahl is the fixed job. Gustafson is the bigger one.
