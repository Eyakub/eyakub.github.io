Inside api, localhost is that container. Use db:5432.

docker compose up reads compose.yaml. It creates the network <project>_default, creates a missing named volume, then starts containers in dependency order.

Compose attaches every service to that network. DNS answers each service name with that container's address. The host hears nothing until a port is published.

api and worker list db and redis under depends_on, so those two start first and together. With no condition, Compose waits only until the process has started.

The db healthcheck runs pg_isready. Exit 0 means Postgres accepts connections. redis has no healthcheck, so service_started is enough.

condition: service_healthy starts api only after db is healthy. ports: 8000:8000 publishes host port 8000. db and redis publish nothing.

worker uses the same image as api. Its command replaces the image CMD, for example celery -A app.worker worker.

localhost:8000 reaches api. With no host IP, Docker publishes on every interface. The host has no route to db or redis.

DNS resolves db, so api connects to db:5432, the container port. ports plays no part. A URL is postgresql://app:pw@db:5432/app.

api pushes the job to redis://redis:6379. The host is the service name, and 6379 is the Redis port. Celery calls this store the broker.

The worker reads redis by name and runs the job. Redis only holds it, so api stays free. Add copies with --scale worker=3.

db writes to the named volume pgdata, outside the container. docker compose down keeps named volumes. docker compose down -v deletes them.
