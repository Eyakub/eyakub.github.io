Ingress

A failed readiness probe removes the Pod. Liveness restarts it.

kubectl apply stores replicas: 3 through the API server into etcd. The card does not start the Pods.

The Deployment controller creates a ReplicaSet, which creates Pods up to 3. You do not create it. A scale is not a rollout.

The scheduler binds a Pod with no node. A Pod is scheduled once. If it cannot start, the replacement is a new Pod.

The kubelet asks the container runtime to start the containers, then reports status. The runtime is not one program.

The default Service is a ClusterIP inside the cluster. It selects Pods by labels. Ready addresses are on EndpointSlices.

Ingress opens HTTP and HTTPS onto the Service only after a controller is installed. Gateway API is for new work.

A gone Pod is replaced, not moved. The card still says 3. A rollout starts only when the template changes. Undo returns that template.
